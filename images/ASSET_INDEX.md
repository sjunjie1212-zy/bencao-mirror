## 7 图正式验收准则

1. Hero、Specimen、Detail 01–05 均须基于与药典基源和药用部位相符的可追溯实物材料；不以活体整株、食物、包装或其他物种替代药材。
2. 图像按角色逐张核验药材身份、部位、尺度和真实形态；错误的种仁/果核、虚构剖面和无证据植物特征一律不批准。
3. **验收单位是每味一张母图。** 七个图位是这张母图的封面/远景/中景/细节派生，按设计共用它——同一味的七张来自同一母图不构成缺陷。要查的是每个图位是否真的承担了各自的观察职责，以及有没有补出母图里不存在的东西。母图本身不得跨味复用，两味共用一个实物照片即判失败。拼版、文字海报、无关内容禁止入正式库。
4. 母图存入 `images/_masters/`，候选图位存入 `images/_candidates/<编号>/`，记录来源/作者/许可、药典或标本依据、候选文件及审核记录。
5. 母图经审核通过、图位逐张核验通过、并经 `scripts/validate_visual_qa.py` 校验后，才将最终版本提交到 `images/` 并解除该味网页隔离；AI 示意应明显标识，不能以实拍标本名义公开。

## 文件与上线规则

1. 在候选目录存储单张图片及来源证据，禁止自动导入脚本直接覆盖 `main/images/`。
2. 更新 QA 登记表：先落母图的 `verified`，再落图位的 `derived_from` 与 `approved`。母图未通过时该味任何图位不得标为 `approved`；任何缺失来源、药用部位未核或视觉存疑的图位同样不得标为 `approved`。
3. 一味七个图位全部审核通过，提交正式资产与 manifest 并核对网页实际引用后才能恢复完整图集。
4. 更新本索引、登记表和发布记录，核对 GitHub Pages 最终部署状态。
